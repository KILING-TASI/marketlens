## 结构化与计算检查

初轮35项中，发现2项时间边界失败，以及15项数据库连接未关闭导致的清理错误。修正后37项通过；加入公开信息回放与来源冲突检查后41项通过；再加入正式更正与原版本保护后44项通过。安装目录中的实际文件也重新运行44项，无失败或错误。

| 检查领域 | 核心不变量 |
|---|---|
| 身份与证据 | 异常无身份；计划/持仓不能替代执行；具体证券、动作、日期和金额需匹配 |
| 时点 | 晚披露、时间未知与尚未发生的执行不确认；晚核验按回放模式限制 |
| 来源与缺失 | 同来源导入幂等；不同来源冲突阻断；NaN/无效批次原子拒绝；零与未知区分 |
| 企业行动 | 份额拆分折算不产生虚假净申购；缺日历或前日数据时降级 |
| 计算 | 历史分位不含当日；权重缺失仍可给样本宽度但不算贡献代理；融资重叠池不相加 |
| 修订与回放 | 原快照不被修改；更正只替代明确引用的旧证据，负修订不解释成卖出 |
| 范围与安全 | 示例与真实数据分区；混合主张逐项判断；文档指令不变为身份依据 |

9步实际调用包括模板生成、CSV导入、按截止计算、快照回放、状态查询、叙事检查、证据创建、人工审核和审核后计算。实际导出中文Markdown与JSON，而不是仅验证文件存在。

## 已落实的优化

1. 对已执行/持仓/业务证据补充发生期与披露期一致性，拒绝“尚未发生但已经执行”。
2. 数据库连接统一释放，Windows连续运行和临时数据清理正常。
3. 将“原已确认状态回放”与“当时公开信息的事后核验”分开，报告明确口径。
4. 多来源同一数据冲突不再静默选取，保留双方依据并阻断依赖值。
5. 正式公告更正需引用旧版本；记录更正调整与新增执行的不同性质。
6. 对“两融净活动”保留字段定义，余额变化不自动变成融资净买入。
7. 修正Skill界面元数据编码，名称、说明和调用示例保持UTF-8。
8. 测试命令在失败时返回非零状态，避免后续检查误判通过。

## 后续真实使用需要验证的内容

真实来源真实性、历史首次可用时间、全ETF与成分覆盖、企业行动因子仍由研究者核对。脚本不会认证公告或自动理解语义。在线数据源、复杂财务、分钟行情和收益预测尚未交付。

建议先用用户已取得的少量真实数据和原公告试用，记录来源冲突、漏检、人工审核时间和结论修订。只有真实使用产生可复核增益后，再扩展接口与预测模块。上述模拟测试不替代这一过程。
